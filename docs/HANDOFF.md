## 这一版做了什么

把 `/tmp/remotion-map-test` 里验证过的路线动画，做成了一个本地网页工作台。启动命令 `pnpm start`，地址 `http://127.0.0.1:5317`。

### 1. 视频组件（`src/video/`）

| 文件 | 作用 |
| --- | --- |
| `config.ts` | `VideoConfig` 类型。工作台编辑的就是这个对象，预览和渲染都只读它 |
| `timeline.ts` | 纯函数：输入配置和帧号，输出这一帧的相机、轨迹、车头、流光、地标、HUD 数值。地图和 HUD 读同一份结果，所以不会出现轨迹落后于画面 |
| `mapStyle.ts` | 自建底图样式：OpenFreeMap 矢量瓦片按主题配色，楼块 3D 拉伸，路线由暗虚线底线和三层发光轨迹组成 |
| `Hud.tsx` | 顶栏、标题、站点进度条、地标卡、总结卡、仪表盘、署名。坐标取自画幅布局，文字和显隐取自配置 |
| `layout.ts` | 三种画幅的 HUD 坐标和镜头取景。9:16 避开小红书顶栏 0–160px、底栏 1700–1920px、右侧 940px 以外 |
| `themes.ts` | 6 套主题的色值，从之前的对比页原样搬过来 |

和 `/tmp` 版相比的改动：

- 场景参数改成从配置读取，不再写死成都、重庆两条路线。
- **镜头动感滑块**（0–100）同时控制三项：转弯时偏航跟随比例、偏航平滑强度、穿行时的缩放。默认 50 对应之前验证过的成片参数，有单元测试守着。
- **环线自动判断**：起终点很近时，用起点到终点的方向定镜头朝向没有意义，这时改成正北朝上。
- **地图站名方位自动计算**：之前重庆示例是手工写的。现在按收尾全景的朝向找每个站最近的邻居，把文字放到背离邻居的一侧。
- **标题按宽度自动缩小字号**，长标题不会超出安全区。
- 渲染时地图 2 倍超采样，预览时 1 倍，保证预览流畅。

### 2. 本地服务（`server/`）

| 接口 | 作用 |
| --- | --- |
| `GET /api/config` | 是否已填 Key（返回打码后的 Key）、输出目录 |
| `POST /api/key` | 校验并保存 Key：先检查是不是 32 位，再真实调一次高德接口，常见错误码都翻译成具体改法 |
| `GET /api/search` | 高德输入提示，返回坐标已从 GCJ-02 转成 WGS-84 |
| `POST /api/route` | OSRM 骑行路网算路 |
| `POST /api/render` · `GET /api/render/:id` | 渲染任务和进度。一次只跑一个任务，单并发、ANGLE 后端，和成片验证时参数一致 |
| `POST /api/reveal` | 在 Finder 里定位成片，只允许输出目录内的文件 |

- 服务只监听 `127.0.0.1`。
- Key 存在 `config.local.json`，已加入 `.gitignore`，仓库里没有任何 Key。

### 3. 工作台前端（`src/app/`）

- **Key 引导**（`KeyGate.tsx`）：没有 Key 时弹出。三步说明，带直达高德控制台的链接，重点提醒选「Web服务」。
- **四个区**（`Panels.tsx`）：
  - 路线：城市、起终点、途经点；可拖动排序，也可用 ↑↓ 按钮；每个点有“弹地标”开关；最多 5 个途经点；可一键互换起终点。
  - 风格：6 张主题缩略图。
  - 字段：画幅、时长、镜头动感（带“恢复默认”）、8 个组件开关。
  - 文案：所有文字都可编辑。
- **搜索框**（`PlaceSearch.tsx`）：边打字边出候选，防抖 220ms，支持方向键和回车。搜到的地名会自动去掉括号里的分店信息，英文名默认用拼音。
- **默认文案**：根据路线自动生成。用户改过的字段不会被覆盖，“按当前路线重置”可以恢复。
- **路线体检**（`src/shared/health.ts`）：路线太短或太长、车速过快（会给出建议时长）、来回折返超过 300 米、相邻地标不到 150 米。
- **实时预览**（`Preview.tsx`）：`@remotion/player` 播放同一个视频组件，9:16 可叠加小红书遮挡区。
- **状态记忆**：存在浏览器 localStorage，刷新页面不丢。第一次打开载入成都示例。

## 已知限制和后续建议

1. 算路固定用骑行路网，因为驾车路网受单行道影响，常常绕远并出现掉头。用户不能选出行方式，这是按需求有意去掉的。
2. 路线体检只提示，不会自动修复。出现折返时要用户自己换途经点。后续可以做“自动尝试附近主路节点”。
3. 时长和镜头动感只影响时间轴，不会重建地图；主题、画幅、路线变化会重建地图，预览会黑一下再出画面。
4. 首次渲染要先打包工程，约 20 秒；第一次运行还会下载约 81MB 的 Chrome Headless Shell。
5. 公益服务（OSRM、OpenFreeMap）有合理使用限制。如果要大规模分发，建议自建 OSRM 或换商用瓦片。

## v0.2.7 3D 玩具车（2026-11-20）

- `src/video/carLayer.ts`：three.js 自定义图层，和 MapLibre 共用 WebGL 上下文与深度缓冲（楼会挡住车）。模型加载后归一化成车头朝正北、Z 朝上、车长 1；每帧按时间轴的车头位置和 `heading`（平滑过的行进方向，`FrameState.heading`）摆放。车长按屏幕像素定（168px，`512 × 2^zoom` 换算），镜头拉远拉近车一样大。图层插在站名下面，站名在有车的主题里推远 3.6em。
- 渲染时首帧会等模型加载完再放行；换主题时按需加、删车图层。`optimizeDeps` 预打包 three.js，否则第一次切到带车的风格时 Vite 发现新依赖会整页刷新。
- 依赖：`three@0.187.0`、`@types/three@0.187.0`。
- 测试：单元测试 32 项；旧主题逐像素一致；预览切换带车风格保持 60fps；180 帧渲染有车 27.8 秒、无车 28.3 秒，3D 车不拖慢渲染。车头方向用顶视图核对过（车灯朝 +Y）。

## v0.2.6 30fps 输出选项（2026-11-19）

- 字段区新增「帧率」：60fps 顺滑（默认）/ 30fps 快一倍。`VideoConfig.fps` 可选，不填为 60。
- 时间轴仍按 60 帧计算（镜头平滑、小车转向、动画节奏都按 60 帧调过），30fps 时 `TravelMap` 把第 n 帧映射到时间轴第 2n 帧，所以 30fps 成片就是 60fps 隔帧取样：第 150 帧和 60fps 第 300 帧逐像素一致。预览也按所选帧率播放。文件名带 `_30fps`。
- 实测（M5，成都示例暗夜青）：60fps 510 帧 70.7 秒 → 30fps 255 帧 41 秒（CLI 含约 8 秒打包，工作台里打包有缓存）。光流 jerk 数值变大是因为每帧位移翻倍，和把 60fps 成片隔帧抽取后测出的数一致，不是新抖动。
- 测试：单元测试 32 项（新增帧数按帧率算）；浏览器里切 30fps 后渲染请求带 `fps: 30`，刷新后保留选择。

### 渲染速度实测（M5，成都示例暗夜青，1080×1920 60fps）

| 方案 | 结果 | 结论 |
| --- | --- | --- |
| 当前（并发 1、2 倍超采样） | 整条 510 帧 70.7 秒 | 基线 |
| 并发 2 / 3 / 4 | 116.5 / 119.5 / 119.5 秒 | 更慢：几个页面抢同一块 GPU |
| 硬件编码（并发 3） | 118.9 秒 | 没用：瓶颈在画面，不在编码 |
| 超采样 2 倍 → 1 倍（240 帧） | 35.4 → 35.1 秒 | 几乎不变，画质 SSIM 0.976，不值得 |
| 每帧不等 idle、瓦片到齐就截图（240 帧） | 35.4 → 30.4 秒 | 快 13%，但和基线画面不完全一致（SSIM 0.985），有截到半成品的风险，没采用 |

瓶颈是单 GPU 上逐帧画地图再截图，每帧约 100ms。能明显提速的只剩改帧率（30fps 帧数减半）或出低清草稿，这两项都改变成片，等用户决定。

## v0.2.2 换风格不卡、换城市清路线（2026-11-19）

- **换风格卡顿**：原来换主题会销毁整个地图再重建，WebGL 上下文、瓦片都要重来，第一次切到新画法时预览卡 1 秒左右（实测钢笔线稿最长一帧 1183ms、微缩模型 967ms）。现在 `mapKey` 不含主题，换主题在原地图上 `setStyle(..., {diff: true})`，瓦片和上下文都保留。实测 7 套平面风格切换后最长一帧都在 18ms 以内，稳定 60fps。地形风格切换时仍要下载海拔数据，预览上显示“地图加载中…”约 1–3 秒，之后稳定在 47–53fps（地形本身更吃 GPU）。渲染不受影响：每个渲染任务只用一套主题，走的还是首次建图的路径，旧主题逐像素一致。
- **换城市不生效**：改城市框只改了文字，已选的点还在原来的城市，又会把搜索锁在原城市，新城市的候选全是灰的。现在城市框失去焦点或回车时，如果和已选点的城市不一样，就清空路线（同 `clearedRoute`），并提示“已换到 X，原来 Y 的路线点清掉了”。只是补“市”字（重庆 → 重庆市）不会清。
- 测试：浏览器脚本 5 项（载入重庆示例 → 改成重庆市不清 → 改成成都清空并提示 → 搜天府广场候选可选）；单元测试 30 项。

## v0.2.0 新增两套画法：手账卡通、山野地形（2026-11-19）

前 6 套是同一种霓虹发光画法换配色。这次在主题里加了可选的画法开关（`flat`、`roadCase`、`traceCase`、`headIcon`、`buildingScale`、`terrain` 等，见 `themes.ts`），不填时和原来完全一样。

- **手账卡通（`toon`）**：奶油纸底、纸张纹理、道路粗描边、楼块压到 0.45 倍高、轨迹是带深色描边的实线，不画任何发光；车头换成画布现画的 Q 版小车，朝向取自时间轴里平滑过的行进方向（前后 120m 路段方向 + 帧域高斯 σ=8）。HUD 文字改用深色。
- **山野地形（`terrain`）**：AWS Open Data 的 Terrain Tiles（terrarium 编码，免费、无需 Key）做 3D 地形，放大 1.6 倍，按海拔着色加山体阴影。署名多一条 `Terrain Tiles © Mapzen`。
- **地形抖动的根因**：MapLibre 默认把镜头中心钉在当前地面高度上，海拔按瓦片分块采样，相邻帧取到的高度会跳，画面上下抖（光流 jerk p99 13px）。改成地图加载完后取一次起点地面高度，之后每帧固定用它（`centerClampedToGround: false` + `jumpTo({elevation})`），jerk p99 降到 0.34px，和旧主题同一水平。
- **测试**：单元测试 27 项（新增：旧主题图层不变、卡通无发光层、地形带 DEM 和阴影、两条示例小车逐帧转向 <13°）；黑金、全息、霓虹三套新旧代码各渲一帧，逐像素一致（PSNR inf）；浏览器里 8 套主题都能切换，没有报错。
- **性能**：M5 上成都卡通 8.5 秒约 89 秒，重庆地形 9.5 秒约 113 秒（原主题 56–74 秒）。地形第一次切换时预览要加载海拔数据，约 7.6 秒，之后约 1 秒。
- **限制**：平原城市（如成都）地形起伏很小，选地形主题看不出区别；工作台没有拦这个，主题说明里写了。

## v0.1.5 删除 Key 的入口（2026-11-19）

- 点右上角「高德 Key」打开弹窗，已保存 Key 时会显示打码后的 Key 和「删除这个 Key」。点了要再确认一次，确认后调用 `DELETE /api/key`。

## v0.1.1 修复（2026-11-16）

用户反馈：输入第二个途经点时“鼠标变成输入光标，点哪里都没用，但视频在播、页面能滚动”。

1. **页面点不动**：根因是整行设成了可拖动（`draggable`），在输入框里按住鼠标选字会触发原生拖拽，浏览器停在拖拽状态。现在只有左侧 `⋮⋮` 把手能拖，整行只负责接收放下。用真实浏览器复现过修复前后：修复前会触发 `dragstart`，修复后不会；用把手拖动排序仍然可用。
2. **同城规则**：高德返回的 `adcode` 前 4 位作为城市码（地级市或直辖市）。其他城市的搜索候选会标灰，显示“不在成都市”，点了也选不上。如果已有的点跨了城市（例如改过城市框），路线区会报错，不会算路，也不能渲染。第一次选点时如果城市框是空的，会自动填上这个点所在的城市。
3. **渲染只在点按钮时发生**：原来就是这样，这次在按钮旁写明了“预览只是播放，不会生成文件”。以下情况按钮不可点，并说明原因：有点没选、跨城市、正在算路、路线过期。搜索防抖 220ms，算路防抖 350ms。
4. **预览不再登记渲染等待**：`delayRender` 和 `idle` 等待只在渲染时用。预览连续播放时地图很少进入 idle，按旧写法每帧都会留下一个监听。

测试：类型检查通过；单元测试 19 项全部通过（新增同城规则 3 项）；`pnpm e2e` 全部通过，**这次包含真实的高德搜索**（用户已填好 Web服务 Key）；浏览器交互脚本 6 项全部通过：输入框里拖动、把手排序、跨城候选标灰、不可选候选点了不生效、未选完不能渲染、改字段时不会自动渲染。
